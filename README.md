# Memescan — стратегия «перевес покупок» для pump.fun

**Режим: только бумажная торговля.** Никаких ключей, кошельков и реальных ордеров.

## Запуск
```bash
python3 server.py            # http://localhost:8787  (нужен только Python 3.9+, без pip install)
python3 server.py --demo     # офлайн-демо на синтетических данных
python3 -m unittest -v tests.test_strategy
```
Публичный Solana RPC часто режет `getTokenLargestAccounts`. Возьми бесплатный ключ Helius/QuickNode:
`SOLANA_RPC_URL="https://mainnet.helius-rpc.com/?api-key=..." python3 server.py` (или вставь его в «Настройки» в интерфейсе).

## Стратегия (вся)
1. **Только pump.fun.** По умолчанию берём монеты, уже мигрировавшие на PumpSwap: на bonding curve пул слишком тонкий, его кладёт одна транзакция (включается в настройках).
   Анти-скам: ликвидность ≥ $50K, монета старше 24ч, объём за 24ч ≥ $200K. On-chain: у создателя ≤ 10%, крупнейший кошелёк ≤ 10%, топ-10 ≤ 35%, кластер ≤ 15%, нет mint/freeze authority.
2. **Вход.** Покупки в $ ≥ ×2 продаж за 15м и за 5м, покупок ≥ $10K, ≥ 25 разных покупателей, на одного покупателя ≤ 30%.
3. **Держим, пока покупки ≥ ×2 продаж** (окно 15м). Выходим, когда перевес падает ниже ×2.
4. **Выходим раньше**, если:
   - **создатель** продал ≥ 10% своих монет;
   - любой из **топ-3 холдеров** продал ≥ 20%;
   - **кластер** связанных кошельков продал ≥ 20%;
   - сработал стоп −15%.

Создатель берётся прямо из блокчейна, из аккаунта bonding curve монеты (поле `creator`), без сайта pump.fun. У монет, созданных до появления этого поля (до весны 2025), создатель не определится: тогда работают только правила для топ-3 и кластеров.

Все пороги задаются в `memescan/config.py` или в «Настройках» интерфейса (сохраняются в `data/config.json`).

## Данные
- **GeckoTerminal** (бесплатно, ~30 запросов в минуту): пулы PumpSwap и трендовые пулы плюс последние 300 сделок пула, из них считаются реальные $ покупок и продаж.
- **Solana RPC**: топ холдеров, владельцы, mint/freeze authority. Кластеры: для каждого топ-кошелька ищется, кто первым прислал ему SOL; кошельки с общим источником (или фондирующие друг друга) образуют кластер. Горячие кошельки бирж в кластеризации не участвуют.
- После входа бот запоминает балансы топ-10 кошельков и проверяет их каждый скан одним RPC-запросом.

Журнал сделок пишется в `data/journal.jsonl`, позиции в `data/state.json` (переживают перезапуск).

## Известные ограничения
- 300 последних сделок у очень активного пула могут покрывать меньше 15 минут: тогда метрика считается по доступному окну.
- Перевод токенов создателем или китом на другой свой кошелёк засчитывается как продажу. Это консервативно: выходим раньше.
- Порог ×2 и для входа, и для удержания одинаковый, поэтому возможны частые входы-выходы около ×2. Если журнал это покажет, поставим вход ×2.5 и удержание ×2.
- ID пулов PumpSwap в GeckoTerminal (`pumpswap`) не проверен на живых данных. Если эндпоинт не ответит, скан всё равно идёт по трендовым и топовым пулам с адресами на `…pump`.
- Кластеризация по первому фондированию эвристическая и не ловит связи через миксеры или биржи.
- Бэктеста нет: исторических сделок с разметкой покупка/продажа в бесплатных API нет. Стратегию проверяем бумажной торговлей.
